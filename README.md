# Group Discount Optimization

Исследовательский проект для задачи выбора предметов из групп с разными коэффициентами скидки на вес и бонуса к полезности.

> **Текущая версия готовит основу проекта. Генератор тестовых данных и алгоритмы решения пока не реализованы.** Они будут добавляться после фиксации формата данных и проверки базовой модели.

## 1. Постановка задачи

Есть **один рюкзак** с максимальной вместимостью `W_max`. Доступные предметы разделены на группы. Каждая группа — это категория кандидатов, для предметов которой действуют собственные проценты снижения учитываемого веса и увеличения полезности. Группы не являются отдельными рюкзаками.

Каждый предмет принадлежит **ровно одной группе**. Из всех групп вместе нужно выбрать ровно `Q` предметов (например, `Q = 10`). Суммарный вес выбранных предметов после применения групповых скидок не должен превышать `W_max`. Среди допустимых наборов требуется максимизировать суммарную полезность после групповых бонусов.

По ответу преподавателя:

- один рюкзак и одно общее ограничение по весу;
- число выбранных предметов во всех группах вместе должно быть ровно `Q`;
- из каждой группы разрешено выбрать от 0 до `Q` предметов, с учётом размера её списка;
- параметры скидки на вес и бонуса к полезности задаются отдельно для каждой группы и находятся в диапазоне от 0 до 50%;
- веса и количество выбираемых предметов целочисленные;
- каждый предмет принадлежит ровно одной группе.

## 2. Математическая модель

Пусть:

- `K` — количество групп;
- `I_k` — список предметов группы `k`;
- `w_ki` — исходный вес предмета `i` из группы `k`;
- `u_ki` — исходная полезность этого предмета;
- `d_k` — процент снижения веса для группы `k`;
- `b_k` — процент увеличения полезности для группы `k`;
- `W_max` — вместимость единственного рюкзака;
- `Q` — точное количество предметов, которое необходимо выбрать.

Введём бинарную переменную решения:

$$
x_{ki} = \begin{cases}1, & \text{если предмет }i\text{ группы }k\text{ выбран,}\\0, & \text{иначе.}\end{cases}
$$

Скорректированный вес выбранного предмета:

$$
\widetilde w_{ki}=w_{ki}\left(1-\frac{d_k}{100}\right).
$$

Скорректированная полезность выбранного предмета:

$$
\widetilde u_{ki}=u_{ki}\left(1+\frac{b_k}{100}\right).
$$

Целевая функция — максимизировать суммарную скорректированную полезность:

$$
\boxed{\max U_{\mathrm{sum}}=\sum_{k=1}^{K}\sum_{i\in I_k}u_{ki}\left(1+\frac{b_k}{100}\right)x_{ki}.}
$$

Ограничение на точное количество выбранных предметов:

$$
\boxed{\sum_{k=1}^{K}\sum_{i\in I_k}x_{ki}=Q.}
$$

Ограничение на общий вес после применения скидок:

$$
\boxed{\sum_{k=1}^{K}\sum_{i\in I_k}w_{ki}\left(1-\frac{d_k}{100}\right)x_{ki}\leq W_{\max}.}
$$

Переменные выбора бинарные: `x_ki ∈ {0, 1}`. Полная версия модели и пояснения находятся в [`docs/mathematical_model.md`](docs/mathematical_model.md).

В README и математическом описании проценты записаны непосредственно через деление на 100. Возможные технические способы точного вычисления будут описаны отдельно, когда начнётся реализация алгоритмов.

## 3. Что пока не фиксируем дополнительно

- Целочисленность полезностей явно не подтверждена в ответе преподавателя; поэтому её не объявляем обязательным свойством математической постановки.
- Преподаватель указал диапазон процентов 0–50%, но не уточнил шаг изменения процентов. Конкретную гранулярность зададим в планируемом генераторе и явно укажем в параметрах эксперимента.
- Правило генерации вместимости и распределения весов/полезностей — это решения экспериментального дизайна, а не часть математической постановки.
- Не добавляем порог активации скидки по количеству предметов: у каждой группы есть свои коэффициенты, которые применяются к каждому выбранному из неё предмету.

## 4. Структура репозитория

```text
configs/                         # будущие конфигурации генерации и экспериментов
  README.md

data/
  examples/                      # небольшие ручные примеры
  generated/                     # будущие сгенерированные экземпляры

docs/
  mathematical_model.md          # постановка задачи и формулы
  data_generation.md              # план генератора, без реализации
  algorithm_plan.md               # план алгоритмов
  repository_setup.md             # создание GitHub-репозитория

src/group_discount_optimization/
  core/
    model.py                     # структуры данных и проверки входа
    loader.py                    # чтение/запись JSON-экземпляров
    evaluation.py                # расчёт скорректированного веса и полезности
  algorithms/                    # будущие brute force и greedy
  experiments/                   # будущий запуск серий и свод результатов

tests/
  test_evaluation.py              # тесты формул и допустимости
  test_model.py                   # тесты структуры входных данных

analysis/                         # анализ экспериментальных результатов
logs/                             # журналы запусков
results/                          # результаты алгоритмов
```

Структура вдохновлена старым проектом [`alenest/knapsack-metaheuristics`](https://github.com/alenest/knapsack-metaheuristics): сохраняются раздельные каталоги для ядра, алгоритмов, конфигураций, данных, запусков и результатов. Но задача и формат входных данных отличаются. Старые данные и результаты не используются как результаты экспериментов по новой задаче.
