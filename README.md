# Group Discount Optimization

Учебно-исследовательский проект по задаче выбора ровно `Q` предметов в один рюкзак. Предметы могут входить в группы, которые дают скидку на учитываемый вес и бонус к полезности, но только после достижения порога. Предмет может не входить ни в одну группу.

В репозитории уже подготовлены математическая модель, загрузчик данных, единый оценщик решения, генератор и 12 зафиксированных экземпляров. Алгоритмы поиска решения — полный перебор и жадный метод — будут добавлены следующим этапом.

## Суть задачи

Есть один рюкзак вместимости `W_max` и `n` уникальных неделимых предметов. Нужно выбрать ровно `Q` различных предметов так, чтобы суммарный учитываемый вес не превышал `W_max`, а суммарная полезность была максимальной.

Каждый предмет `i` имеет исходный вес `w_i` и полезность `u_i`. Предмет может принадлежать не более чем одной группе. Группа `k` задаёт:

- порог `t_k` — сколько предметов группы нужно выбрать, чтобы эффекты включились;
- скидку на вес `d_k` в процентах;
- бонус к полезности `b_k` в процентах.

Если из группы `k` выбрано `s_k` предметов, то индикатор активации равен

```text
y_k = 1, если s_k >= t_k,
y_k = 0, если s_k < t_k.
```

Для предмета из группы `k` учитываемые вес и полезность равны

```text
w~_i = w_i * (1 - d_k * y_k / 100),
u~_i = u_i * (1 + b_k * y_k / 100).
```

Оба эффекта включаются одновременно. При достижении порога скидка и бонус применяются ко всем выбранным предметам группы, а не только к предметам сверх порога. Для предметов вне групп `w~_i = w_i` и `u~_i = u_i`.

Итоговая модель:

```text
max  sum u~_i * x_i
при  sum x_i = Q,
     sum w~_i * x_i <= W_max,
     x_i in {0, 1}.
```

Группы не являются отдельными рюкзаками: у всех предметов один общий лимит веса и одно общее требование выбрать ровно `Q` предметов.

Подробная постановка и линеаризация порога для точных решателей описаны в [`docs/mathematical_model.md`](docs/mathematical_model.md).

## Что уже реализовано

- `Item`, `Group`, `Instance` и загрузчик `load_instance` с проверкой целостности экземпляра.
- Единый оценщик `evaluate_selection`: считает выбранные предметы по группам, активирует пороговые эффекты, проверяет ровно `Q` предметов и вместимость.
- Генератор экземпляров v4 с фиксированным seed, `manifest.csv` и `checksums.sha256`.
- 12 готовых экземпляров `n = 12..100`, `Q = 10`.
- Автоматические тесты модели, загрузчика, оценщика, генератора и неизменности набора данных.

Алгоритмы поиска оптимального решения в текущей версии ещё не реализованы. Оценщик уже позволяет проверять любые наборы предметов, поэтому алгоритмы можно добавлять без изменения формата данных и правил задачи.

## Набор данных

В `data/` лежат 12 фиксированных экземпляров — по одному на каждый размер:

| Число предметов `n` | Выбрать ровно `Q` | Экземпляров |
|---:|---:|---:|
| 12, 15, 18, 20, 22, 25 | 10 | 1 на размер |
| 30, 40, 50, 60, 75, 100 | 10 | 1 на размер |

Параметры набора:

- 2–3 непересекающиеся группы в каждом экземпляре;
- порог группы 4 или 5 предметов;
- скидка на вес 25–50%;
- бонус полезности 0–50%;
- исходные веса и полезности — целые числа от 1 до 100;
- в каждом экземпляре есть предметы вне групп.

Экземпляры уже сохранены. Для обычных запусков алгоритмов генератор не нужен: он предназначен для намеренного создания нового набора.

### Формат экземпляра

Каждый экземпляр находится в каталоге `data/n_<n>/instance_001/` и состоит из двух файлов.

`data.npz` содержит массивы:

- `item_ids` — постоянные ID всех предметов;
- `weights` — исходные веса;
- `utilities` — исходные полезности;
- `group_001_item_ids`, `group_002_item_ids`, ... — ID предметов каждой группы.

Предмет хранится в общих массивах один раз. Списки групп не пересекаются. ID, которых нет ни в одном групповом списке, принадлежат предметам вне групп.

`meta.json` содержит:

- `format_version` — версия формата, сейчас `4`;
- `n`, `target_item_count`, `capacity`;
- `group_count`, `group_membership_count`, `ungrouped_item_count`;
- список групп с `item_count`, `min_selected_for_discount`, `weight_discount_percent`, `utility_bonus_percent` и именем массива ID;
- `seed` и параметры генерации;
- контрольное допустимое и недопустимое распределение предметов, использованное при создании экземпляра.

Важно не путать `item_count` — число предметов в группе — и `min_selected_for_discount` — порог активации эффектов. Это разные величины.

`data/manifest.csv` содержит краткий индекс всех экземпляров. `data/checksums.sha256` фиксирует контрольные суммы файлов набора, поэтому случайное изменение данных обнаруживается тестами.

## Загрузка и оценка решения

```python
from group_discount_optimization import evaluate_selection, load_instance

instance = load_instance("data/n_20/instance_001")

# Для примера берём первые Q ID. Конкретный набор зависит от алгоритма.
selected_ids = [item.item_id for item in instance.items[: instance.target_item_count]]
result = evaluate_selection(instance, selected_ids)

print("n:", instance.n)
print("Q:", instance.target_item_count)
print("Вместимость:", instance.capacity)
print("Выбрано по группам:", result.group_selected_counts)
print("Активные группы:", result.active_group_ids)
print("Суммарный вес:", result.total_weight)
print("Суммарная полезность:", result.total_utility)
print("Допустимо:", result.feasible)
```

`evaluate_selection` — единственное место, где реализованы пороговые правила. Будущие алгоритмы должны передавать в него наборы ID и сравнивать полученные значения, а не повторять расчёт скидок и бонусов самостоятельно.

Основные поля результата:

- `selected_item_ids` — выбранные ID в отсортированном виде;
- `group_selected_counts` — сколько предметов выбрано из каждой группы;
- `active_group_ids` — группы, достигшие порога;
- `total_weight`, `total_utility` — итоговые значения с учётом эффектов;
- `count_constraint_satisfied`, `capacity_constraint_satisfied`, `feasible` — проверки ограничений.

## Генерация нового набора

Генератор создаёт файлы `data.npz`, `meta.json`, `manifest.csv` и `checksums.sha256`. Стандартная команда перезаписывает содержимое `data/`:

```bash
python -m group_discount_optimization.generator --seed 42
```

Чтобы не изменять зафиксированный набор, укажите отдельный каталог:

```bash
python -m group_discount_optimization.generator \
    --output data/experiment \
    --sizes 15 20 30 \
    --instances-per-size 2 \
    --q 10 \
    --seed 123
```

Одинаковые параметры и `seed` дают одинаковые массивы и метаданные. После намеренной перегенерации стандартного набора нужно проверить, что контрольные суммы обновились, и запустить тесты.

## Проверка проекта

Из корня проекта:

```bash
python -m pytest
```

Тесты проверяют, в частности, что:

- ниже порога оба групповых эффекта выключены;
- ровно на пороге оба эффекта включаются одновременно;
- эффекты применяются ко всем выбранным предметам группы;
- предметы вне групп не получают скидку и бонус;
- пересечения групп отклоняются загрузчиком и моделью;
- все 12 экземпляров загружаются и соответствуют параметрам набора;
- в каждом экземпляре есть допустимое и недопустимое контрольные распределения;
- контрольные суммы подтверждают неизменность сохранённых файлов;
- генератор воспроизводим при одинаковом seed.
