# Математическая модель задачи с пороговыми групповыми скидками

## 1. Смысл задачи

Есть один рюкзак вместимости `W_max` и единый набор из `n` уникальных предметов. Нужно выбрать ровно `Q` различных предметов. У каждого предмета есть постоянный ID, исходный вес и полезность.

Есть `K` групп. Группа — это список ID предметов, к которым относится её условие скидки. **Один предмет может входить в несколько групп.** Поэтому группы не обязаны быть непересекающимися, а сумма размеров их списков может быть больше `n`.

У каждой группы `k` заданы:

- `min_selected_for_discount` — порог `t_k`, то есть сколько предметов из этой группы нужно выбрать для активации скидки;
- `weight_discount_percent` — процент скидки на вес, `d_k`;
- `utility_bonus_percent` — дополнительный бонус к полезности, `b_k`.

`item_count` — это только размер списка предметов группы. Это **не** порог скидки. Порог хранится отдельно в `min_selected_for_discount`.

## 2. Подтверждённое правило порога

Пусть `G_k` — множество ID предметов группы `k`, а `x_i` показывает, выбран ли предмет `i`:

\[
s_k=\sum_{i\in G_k}x_i.
\]

Скидка группы активируется, когда выбрано не меньше порога:

\[
y_k=\begin{cases}
1,&s_k\ge t_k,\\
0,&s_k<t_k.
\end{cases}
\]

Если порог достигнут, скидка применяется **ко всем выбранным предметам этой группы**, а не только к предметам сверх порога. Например, при пороге 4 скидка действует на все 4 выбранных предмета и продолжает действовать, если выбрано 5, 6 и более.

Это соответствует пояснению преподавателя: «скидка начинается с 3 выбранных элементов» и примеру, где при `Q = 10` разумный порог одной группы — 4–5 предметов.

## 3. Вес и полезность

Для предмета `i`, который входит ровно в одну группу `k`, его учитываемый вес равен:

\[
\widetilde w_i=w_i\left(1-\frac{d_k y_k}{100}\right).
\]

Таким образом, до достижения порога предмет учитывается с исходным весом, а после достижения порога скидка распространяется на все выбранные предметы группы.

Полезность с бонусом из прежней версии проекта пока сохраняется отдельно от порога скидки:

\[
\widetilde u_i=u_i\left(1+\frac{b_k}{100}\right).
\]

В первом новом наборе `utility_bonus_percent = 0` для всех групп: преподаватель попросил сначала исследовать именно эффект весовых скидок 25–50%. Поэтому бонус не влияет на результаты начальных тестов. Его дальнейшую семантику при пороговой модели при необходимости следует подтвердить отдельно.

## 4. Оптимизационная задача для непересекающихся групп

Для текущих начальных тестов генератор создаёт непересекающиеся группы. В этой части модели каждый предмет `i` принадлежит одной группе `g(i)`:

\[
\max\quad \sum_{i=1}^{n}u_i\left(1+\frac{b_{g(i)}}{100}\right)x_i
\]

при условиях

\[
\sum_{i=1}^{n}x_i=Q,
\]

\[
\sum_{i=1}^{n}w_i\left(1-\frac{d_{g(i)}y_{g(i)}}{100}\right)x_i\le W_{\max},
\]

\[
x_i\in\{0,1\},\qquad i=1,\ldots,n,
\]

а активация каждой группы определяется условием из раздела 2.

Важно: вес теперь нельзя окончательно уменьшить при генерации предмета. Он зависит от выбранного набора, потому что от этого набора зависит достижение порога.

## 5. Линеаризация для точных математических решателей

Если модель будет переноситься в ILP/CP-SAT, можно ввести бинарную переменную `y_k` активации скидки и переменную `z_ik = x_i y_k` для каждого членства предмета `i` в группе `k`.

Условие порога:

\[
s_k\ge t_k y_k,
\]

\[
s_k\le (t_k-1)+(|G_k|-t_k+1)y_k.
\]

Линеаризация произведения бинарных переменных:

\[
z_{ik}\le x_i,\quad z_{ik}\le y_k,\quad z_{ik}\ge x_i+y_k-1.
\]

Для непересекающихся групп это позволяет записать вес:

\[
\sum_i w_i x_i-\sum_k\sum_{i\in G_k}\frac{w_i d_k}{100}z_{ik}\le W_{\max}.
\]

В текущем проекте полный перебор и жадный алгоритм ещё не реализованы; формулы нужны для однозначного определения оценки набора и будущей реализации.

## 6. Пересекающиеся группы: что поддерживается и что пока не определено

Структура данных поддерживает пересечения: группы содержат ссылки на общие `item_id`, а предмет физически хранится в экземпляре только один раз. При подсчёте порога предмет учитывается в каждой группе, в которую он входит.

Однако преподаватель пока не уточнил, как считать скидку на предмет, если он одновременно входит в несколько групп, пороги которых достигнуты. Например, не установлено, должны ли скидки складываться, применяться последовательно или выбираться по какому-либо правилу.

Поэтому:

- начальный набор для тестов использует непересекающиеся группы — так можно исследовать пороги и распределение выбора без выдумывания правила;
- загрузчик умеет прочитать пересекающиеся списки групп;
- оценщик корректно обрабатывает предмет, который принадлежит нескольким группам, если скидка активировалась только в одной из них;
- если один предмет попадает под несколько активных скидок, оценщик выдаёт `AmbiguousGroupBenefitError`, а не применяет произвольное правило.

До выбора правила объединения скидок не следует запускать оптимизационные эксперименты на экземплярах, в которых один выбранный предмет может получить скидки одновременно от нескольких активных групп.

## 7. Параметры первого набора синтетических данных

Эти параметры выбраны для первоначальной проверки, а не являются дополнительными требованиями математической задачи:

| Параметр | Значение |
|---|---:|
| Число экземпляров | 12 |
| Уникальных предметов `n` | 12, 15, 18, 20, 22, 25, 30, 40, 50, 60, 75, 100 |
| Точное число выбираемых предметов `Q` | 10 |
| Число групп `K` | 2 или 3 |
| Порог каждой группы | 4 или 5 |
| Скидка на вес | 25–50% |
| Бонус к полезности | 0% |
| Вес и полезность | целые числа 1–100 |

Для `Q = 10` пороги 4–5 позволяют наблюдать, как достижение порога одной или нескольких групп влияет на распределение выбранных предметов между ними. Вместимость формируется так, чтобы существовал допустимый контрольный набор и одновременно существовал более тяжёлый набор с тем же распределением количества предметов по группам, который не помещается.

## 8. Термины в файлах

- `n` — количество уникальных предметов в экземпляре;
- `item_id` — постоянный уникальный идентификатор предмета;
- `item_count` группы — количество ID в списке этой группы;
- `min_selected_for_discount` — порог активации скидки;
- `Q` / `target_item_count` — сколько уникальных предметов нужно выбрать во всём экземпляре;
- `K` / `group_count` — число групп.
