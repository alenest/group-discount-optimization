# План реализации алгоритмов

## Текущий этап

Подготовлены новая модель данных v3, генератор с порогами скидок, сохранённый тестовый набор из 12 экземпляров и единый оценщик решений. Алгоритмы оптимизации ещё не реализованы.

## 1. Ручная проверка сценариев

Сначала проверить `evaluate_selection` на наборах, где:

- группа выбрана ниже порога — скидка не активна;
- выбран ровно порог — скидка активна для всех выбранных предметов группы;
- выбрано больше порога — скидка продолжает действовать на все выбранные предметы;
- достигается порог одной группы и двух групп;
- нарушено точное количество `Q` или вместимость.

## 2. Полный перебор для малых n

Перебирать комбинации ровно из `Q` уникальных ID из общего набора предметов. Для каждой комбинации вызывать единый оценщик, отбрасывать недопустимые решения и сохранять допустимое решение с максимальной полезностью.

Число комбинаций до проверки вместимости равно `C(n, Q)`. Поэтому полный перебор предназначен для малых экземпляров; для `n=100` и `Q=10` он уже не является быстрым.

## 3. Жадный алгоритм

После проверки точного алгоритма разработать жадную эвристику, учитывающую, что ценность выбора зависит от того, приблизит ли предмет группу к её порогу. Критерий жадности является частью метода, а не заданным свойством математической модели.

## 4. Сравнение

Сравнивать найденные полезности, суммарный вес, распределение предметов по группам, достигнутые пороги и время работы. На малых экземплярах результат жадного метода сравнивать с оптимумом полного перебора.

## 5. Что пока не делать

Не запускать крупную серию экспериментов и не переходить к метаэвристикам, динамическому программированию или CP-SAT, пока новая модель и оценщик не проверены на простых сценариях.
