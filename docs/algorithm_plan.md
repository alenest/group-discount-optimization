# План дальнейшей реализации алгоритмов

## Текущий этап

Формат данных v4, непересекающиеся группы, возможность предметов вне групп, единое пороговое включение скидки на вес и бонуса полезности, оценщик и 12 сохранённых экземпляров `n <= 100` зафиксированы. Полный перебор и жадные алгоритмы реализованы, расширенные эксперименты проведены, результаты собраны в [`../reports/report.md`](../reports/report.md). Все методы читают данные из каталога экземпляров и используют `evaluate_selection`.

## 1. Проверка простых сценариев

Сначала вручную проверить:

- выбор из группы меньше порога — оба эффекта выключены;
- выбор ровно порогового числа — оба эффекта включены;
- выбор больше порога — оба эффекта продолжают действовать;
- скидка и бонус применяются ко всем выбранным предметам активной группы;
- предмет вне групп не получает ни скидку, ни бонус;
- итоговое решение содержит ровно `Q` предметов и укладывается в общий лимит.

## 2. Точный метод для малых экземпляров

Полный перебор проверяет все сочетания ровно из `Q` уникальных предметов. Для каждой комбинации вызывается `evaluate_selection`; среди допустимых решений выбирается решение с максимальной полезностью. Число комбинаций до проверки вместимости равно `C(n,Q)`, поэтому полный перебор нужен прежде всего для малых `n`.

## 3. Жадный метод

После проверки оценщика и точного метода разработать эвристику, учитывающую как непосредственное соотношение полезности и веса предмета, так и возможность довести выбранную группу до порога. Критерий жадности должен быть явно описан и проверен сравнением с точным решением на малых экземплярах.

## 4. Первичный эксперимент

Следовать рекомендации преподавателя: сначала 10–15 простых экземпляров, размеры до 100, 2–3 группы; смотреть, как выбранные предметы распределяются между группами и как достижение порога влияет на решение. Не начинать с масштабных автоматизированных экспериментов и метаэвристик.

## 5. Сравнение точного и жадного методов

1. На малых `n` (ориентир — `n = 12..25`) запустить полный перебор и жадный алгоритм на одних и тех же экземплярах. Чтобы результаты не зависели от одного случайного экземпляра, брать по 10 экземпляров на размер.
2. Для каждого экземпляра зафиксировать оптимум, результат жадного алгоритма, отклонение в процентах, время работы и распределение выбранных предметов по группам.
3. Отдельно отметить, в каких случаях жадный алгоритм достигает оптимума и в каких — нет.
4. На `n = 30..100` запустить только жадный алгоритм; сравнение с оптимумом там уже не проводится, оцениваются устойчивость, время и структура решения.
5. Большие `n` (1000, 5000) подключать только после согласования с руководителем и только для жадного алгоритма.

Метрики: суммарная полезность, допустимость, отклонение от оптимума, доля оптимальных решений, время работы, число активных групп, число выбранных предметов по группам и вне групп.

## 6. Связь с тезисом МНТК

Содержательная часть тезиса не только постановка, но и сравнение методов: точный перебор на малых `n` и жадный алгоритм на всех доступных размерах. Структура тезиса и план работы собраны в [`thesis_plan.md`](thesis_plan.md), текст тезиса находится в [`thesis.md`](thesis.md).

## 7. Реализация и результаты

Реализованы:

- `solve_exhaustive` — полный перебор ровно `Q` предметов;
- `solve_greedy_ratio` — базовый жадный алгоритм по отношению полезности к весу;
- `solve_greedy_group_aware` — жадный алгоритм с групповыми пакетами и перебором распределения мест по группам;
- `solve_exhaustive_no_groups` и `solve_greedy_no_groups` — базовые решения без групповых эффектов;
- `experiment.py` — запуск методов и сохранение `results.csv`;
- `analysis.py` — сводная таблица, графики и объединение нескольких `results.csv`.

Для графиков использованы 180 экземпляров: по 10 на каждый размер `n = 12..100` (на `n = 24` и `25` по 5 экземпляров в отдельном наборе). Полный перебор запускался при `n <= 25`. Жадный алгоритм с учётом групп был допустим на всех 180 экземплярах и на `n <= 25` уступил оптимуму в среднем на 0.26%, а на `n = 100` работал в среднем 0.41 с. Базовый жадный алгоритм по отношению `u/w` оказался допустим в 81.4% случаев на малых `n` и в 92.8% случаев на всём наборе. Без групповых эффектов допустимое решение нашлось только для 70.6% экземпляров.

Команды воспроизведения:

```bash
python -m group_discount_optimization.experiment --data data_repeated --output reports/repeated_main --exhaustive-max-n 22
python -m group_discount_optimization.experiment --data data_repeated_2425 --output reports/repeated_2425 --exhaustive-max-n 25
python -m group_discount_optimization.analysis --results reports/repeated_main/results.csv reports/repeated_2425/results.csv --output reports --merge-output reports/results.csv
```
