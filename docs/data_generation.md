# Генератор тестовых экземпляров v3

Генератор находится в `src/group_discount_optimization/generator.py`. Он создаёт готовые экземпляры с пороговыми групповыми скидками. Алгоритмам нужно загружать сохранённые файлы; генератор запускается только при создании или намеренном пересоздании набора.

## Текущий набор

В `data/` включены 12 экземпляров с `n` от 12 до 100 уникальных предметов. Во всех экземплярах `Q = 10`, число групп — 2 или 3, пороги — 4 или 5, скидки — 25–50%, веса и полезности — целые 1–100. Бонус полезности равен нулю, чтобы первые тесты показывали именно эффект весовой скидки.

Размер `n` — число уникальных предметов. Предмет хранится один раз, даже если в будущем будет ссылаться из нескольких групп.

## Формат хранения

Каждый экземпляр — каталог с `data.npz` и `meta.json`:

```text
data/
├── manifest.csv
├── n_12/instance_001/
│   ├── data.npz
│   └── meta.json
└── ...
```

Массивы предметов хранятся один раз:

- `item_ids` — уникальные ID;
- `weights` — исходные веса, позиционно соответствующие `item_ids`;
- `utilities` — исходные полезности, позиционно соответствующие `item_ids`.

Каждая группа хранит отдельный список ссылок, например `group_001_item_ids`. В `meta.json` у группы есть:

- `item_count` — длина её списка ID;
- `min_selected_for_discount` — отдельный порог скидки;
- `weight_discount_percent` — скидка на вес;
- `utility_bonus_percent` — бонус полезности.

Сумма `item_count` по группам может превышать `n`, если группы пересекаются. Предмет при этом не дублируется в массивах `item_ids`, `weights`, `utilities`.

## Перегенерация стандартного набора

Из корня проекта:

```bash
python -m pip install -e ".[dev]"
python -m group_discount_optimization.generator --seed 42
```

Команда создаст стандартные 12 экземпляров в `data/` и обновит `data/manifest.csv`. При обычном режиме перезаписи генератор предварительно удаляет старые каталоги `n_*` и прежний `manifest.csv`, поэтому в папке не останутся экземпляры старой модели (например, прежние `n_1000` и `n_5000`). Повторный запуск с тем же seed даёт те же данные.

## Другой небольшой набор

Например, 3 экземпляра на размеры 15, 20 и 30:

```bash
python -m group_discount_optimization.generator --output data/experiment --sizes 15 20 30 --instances-per-size 3 --min-groups 2 --max-groups 3 --q 10 --seed 123
```

`--output` лучше направлять в отдельный каталог, чтобы не затереть стандартный комплект.

## Оценка решения

Для расчёта выбранного набора используй единую функцию `evaluate_selection`. Она считает, сколько предметов выбрано из каждой группы, какие пороги достигнуты, применяет скидку ко всем выбранным предметам активированной группы и проверяет обе части ограничений: ровно `Q` предметов и вместимость.

```python
from group_discount_optimization import evaluate_selection, load_instance

instance = load_instance("data/n_20/instance_001")
result = evaluate_selection(instance, {1, 2, 3, 4, 11, 12, 13, 14, 15, 16})

print(result.group_selected_counts)
print(result.active_group_ids)
print(result.total_weight, result.capacity)
print(result.total_utility)
print(result.feasible)
```

Если выбранный предмет входит в несколько групп, но порог достигнут только в одной из них, к предмету применяется скидка этой активной группы. Если для одного предмета одновременно активны несколько скидок, оценщик выдаёт явную ошибку: правило объединения таких скидок ещё не утверждено.
